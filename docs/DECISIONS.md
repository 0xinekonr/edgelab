## 2026-05-20：将 EdgeLab 定位为 Java + C++ 工业 IoT 项目

决策：

使用工业 IoT 边缘网关与云端监控平台作为练手项目。

背景：

用户希望保持 Java Web / Spring 熟练度，同时学习 C++ 语法、工程实践和 Java/native 协作方式。

影响：

- Java 负责云端业务能力。
- C++ 负责设备侧 / 边缘侧模拟、协议解析、缓冲和性能相关工作。
- 项目可以自然扩展到分布式、并发和数据处理主题。

## 2026-05-20：先使用 Spring Boot 单体服务

决策：

在 Spring Cloud 拆分前，先用单体 Spring Boot 后端建立最短业务链路。

背景：

当前优先级是让数据链路清晰，并手动练习 Java Web 开发。

影响：

- 降低早期复杂度。
- API 契约和领域模型稳定后，再拆服务。

## 2026-05-20：native 侧使用 CMake

决策：

C++ 项目使用 CMake，而不是 Visual Studio 专属 `.sln`。

背景：

项目需要同时适配 Visual Studio、CLion，以及后续 WSL / Linux。

影响：

- C++ 构建逻辑更可移植。
- IDE 可以变化，但项目结构不需要跟着变化。

## 2026-05-26：日常 C++ 编辑优先使用 CLion，工具链保持 MSVC

决策：

当 CLion 提供更顺手的编辑体验时，使用 CLion；Windows 编译工具链仍使用 MSVC。

背景：

用户熟悉 IntelliJ 家族。Visual Studio 的补全和配置体验不够顺畅。

影响：

- 日常编辑可以在 CLion 中完成。
- Windows native 构建行为仍与 MSVC 对齐。

## 2026-05-26：使用 clang-format 统一 C++ 源码格式

决策：

`native/.clang-format` 是 C++ `.h` 和 `.cpp` 的格式依据。

背景：

IDE 格式设置发生冲突。

影响：

- 格式规则归项目所有，不依赖单个 IDE。
- CMake 文件保持人工维护的局部一致风格。

## 2026-05-26：头文件使用 include guard

决策：

使用 `#ifndef` / `#define` include guard，不使用 `#pragma once`。

背景：

用户询问 C++ 头文件保护方式的标准性和严谨性。include guard 是标准、可移植写法。

影响：

- 头文件稍微更啰嗦。
- 更符合严格可移植和企业规范习惯。

## 2026-05-26：遥测采集保持只读

决策：

`VirtualDevice::collect_temperature()` 不修改设备状态。

背景：

用户指出 `collect_temperature()` 从语义上是读取数据，不应隐藏状态变化。

影响：

- `collect_temperature()` 保持 `const`。
- 温度变化通过 `apply_temperature_delta()` 或 profile 编排完成。
- 设计更容易理解和测试。

## 2026-06-02：采用轻量但有效的测试策略

决策：

优先推进项目，对关键逻辑写聚焦测试，不在每个微小改动上进行过重测试仪式。

背景：

用户认为过多时间花在构建和测试上，影响项目推进节奏。

影响：

- 参数解析、校验、协议、跨语言边界仍要测试。
- 大功能块结束时做聚焦验证。
- 阶段收尾、push 或 PR 前做更完整验证。

## 2026-06-18：C++ 重点机制使用教学型代码注释

决策：

在 C++ 源码中，遇到 Java 开发者不熟悉的 C++ 独有机制时，必须写分层的教学型注释。

背景：

用户指出 `http_client` 代码包含 RAII、移动语义、C API 资源封装、socket 生命周期等大量 C++ 特有内容，如果没有代码内注释，很难边写边学。

影响：

- C++ 重点机制应直接在代码旁解释，而不是只在聊天中解释。
- 注释同时解释“做了什么”“为什么这样写”和“与 Java 的差异”。
- 网络、协议、并发、内存和 C API 适配等底层模块必须有类、方法和关键步骤三个层级的注释。
- `constexpr`、`explicit`、`operator=`、`this` / `*this`、`= delete`、移动语义、`noexcept`、指针所有权、模板参数等 Java 开发者陌生点必须就地说明。
- 简单语法和显而易见逻辑不需要逐句复述，但不能以避免注释噪音为由省略核心流程说明。
