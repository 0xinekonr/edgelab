# EdgeLab 学习与开发总计划

> 本文档用于对齐 EdgeLab 项目的长期学习路线和开发阶段。它只描述整体方案、阶段目标、学习重点、验收标准和推进顺序，不记录具体代码实现细节。

## 1. 项目目标

EdgeLab 是一个围绕工业 IoT 场景设计的 Java + C++ 综合练手项目。

项目核心目标有四个：

1. 保持并提升 Java Web 手动开发能力。
2. 系统学习 Spring Boot、后续 Spring Cloud 及相关企业级后端技术栈。
3. 从零学习 C++，逐步掌握语法、工程组织、数据结构、协议处理、并发和性能优化。
4. 理解 Java 与 C++ 在真实生产系统中的协作方式，以及哪些场景适合让 C++ 承担核心模块。

本项目不追求一开始就“大而全”，而是按阶段演进。每个阶段都应该能独立运行、测试和提交。

## 2. 业务背景

EdgeLab 模拟的是工业 IoT 边缘网关与云端监控平台。

在真实工业场景中，工厂、仓库、机房、电站、冷链系统等环境会部署大量设备和传感器。这些设备会持续产生运行数据，例如温度、湿度、压力、电压、电流、转速、状态码和故障码。

这些数据通常不会全部由云端系统直接从设备读取。更常见的方式是：

1. 设备或传感器产生原始数据。
2. 边缘网关靠近设备侧，负责采集、解析、过滤、缓存和转发。
3. 云端平台接收网关上报的数据。
4. 云端平台进行设备管理、状态监控、告警判断、历史查询和统计分析。

这个业务领域适合 Java + C++ 协同练习：

- C++ 适合设备侧、边缘侧、高性能采集、协议解析、缓冲队列和资源受限环境。
- Java 适合云端业务系统、Web API、数据持久化、权限管理、消息队列、微服务治理和大数据生态集成。

## 3. 总体架构方向

项目整体分为四类模块：

1. Java 云端后端
2. C++ 设备模拟器
3. C++ 边缘网关
4. 本地基础设施与部署环境

早期阶段采用单体 Spring Boot 服务，降低学习负担。等业务流程稳定后，再逐步引入数据库、缓存、消息队列、微服务拆分和大数据处理。

C++ 侧从简单设备模拟器开始，逐渐演进到协议编解码模块、边缘网关、缓冲队列、批量上报和并发处理。

整个项目最终应能在本地完整模拟：

1. 多台设备产生数据。
2. C++ 边缘网关接收并处理数据。
3. Java 云端服务接收数据。
4. 云端完成存储、告警、查询和统计。
5. 开发者可以通过接口或管理端观察系统运行状态。

## 4. 开发环境策略

本项目尽量贴近 Java 和 C++ 各自常见的开发习惯。

Java 侧：

- 使用 Windows 侧开发。
- 使用 IntelliJ IDEA。
- 使用 JDK 17。
- 使用 Spring Boot 3.x。
- 初期以单体服务为主，后续再进入 Spring Cloud。

C++ 侧：

- 优先使用 Visual Studio，方便新手学习调试。
- 使用 CMake 管理工程，保持跨平台能力。
- 代码尽量使用标准 C++，避免过早依赖平台专有能力。
- 后续定期通过 WSL 验证 Linux 编译和运行。

基础设施：

- MySQL 和 Redis 运行在 WSL 中。
- 后续引入 Kafka、Docker Compose 和其他组件。
- 部署阶段再集中学习 Linux、容器和服务编排。

## 5. 开发流程原则

项目采用接近企业开发的流程。

1. `main` 分支保持稳定。
2. 每个阶段使用独立 feature 分支。
3. 每个可验证的小目标完成后进行 Git 提交。
4. 阶段完成后推送分支并通过 PR 合并。
5. 每个阶段必须有明确验收标准。
6. 不在未验证的情况下进入下一阶段。
7. 重要设计、踩坑和概念需要写入学习笔记。

测试原则：

1. 新增关键行为前优先写测试。
2. Java 侧逐步建立单元测试、Web 层测试和集成测试。
3. C++ 侧逐步建立基础单元测试和协议测试。
4. 每个阶段结束前必须运行对应测试。

代码质量原则：

1. 保持模块职责清晰。
2. 控制每一步的复杂度。
3. 不提前堆砌框架和抽象。
4. 先保证业务流程清楚，再逐步增强工程能力。
5. 注释解释关键业务含义、重要配置和不明显的实现原因。

## 7. 阶段推进规则

每个阶段开始前确认：

1. 当前分支正确。
2. 上一阶段测试通过。
3. 工作区没有无关修改。
4. 学习笔记已记录上一阶段关键内容。

每个阶段开发中遵守：

1. 先明确目标和验收标准。
2. 先完成最小可运行版本。
3. 再补充质量、异常和测试。
4. 不跳跃引入后续阶段技术。

每个阶段结束前确认：

1. 代码可以运行。
2. 测试通过。
3. 文档更新。
4. Git 提交完成。
5. 必要时推送远程分支。
